# P139 認臉記名（Faces & Names）V0.4 系統規格

## 1. 產品定位

以照片練習記住同一機構內適合公開學習的人物姓名。正式名稱為「認臉記名｜Faces & Names」。畫面以較大字級並列呈現 Dale Carnegie 人際互動原則：「記住一個人的名字」／“Remember a person's name.”玩家免登入；管理者需登入管理群組及人物資料。

## 2. 角色

| 角色 | 權限 |
|---|---|
| 公開玩家 | 選擇已發布群組與認識優先級、進行填答；個人錯誤與答題統計只存在本機瀏覽器 |
| 系統管理者 | 建立群組；管理各群組人物、別名、公開照片及認識優先級 |
| 群組管理者 | V0.4 暫由系統管理者兼任；尚未開放委派其他群組管理者 |

第一位系統管理者由 SQL Editor 初始化，Email 為 `bagilu@gmail.com`。一般玩家不需 P130 帳號。

## 3. 公開群組資料

第一批群組規劃為「行政主管群組」及「各系教師群組」。群組名稱、人物姓名、別名及照片皆供匿名玩家查詢及學習；管理者須確認資料適合公開後再新增。學生班級私人照片不納入 V0.4。

## 4. 出題與個人紀錄

- 依人物設定的認識優先級出題：最應該認識、應該認識、可以認識。
- 每輪隨機排列，同一輪盡量不重複，完成後重新洗牌。
- 正式姓名及別名皆可判定為正確答案。
- 錯答時即時顯示正確姓名；若輸入同群組其他人物的姓名或別名，提示人物混淆。
- 之前的錯誤答案與練習統計存在瀏覽器 `localStorage`，不傳送到資料庫。

## 5. 資料與權限

- P139 自有資料表全部啟用 RLS，匿名與登入者均無直接資料表權限。
- 玩家僅可執行 `p139_public_list_groups`、`p139_public_list_people`、`p139_public_check_answer` 三個公開 RPC。
- 群組建立需通過 `p139_is_system_admin()`；人物管理 RPC 需驗證群組管理權限。
- 照片存在公開讀取的 `p139-public` bucket；匿名者無照片寫入權限。
- 上傳前在瀏覽器縮小照片尺寸並壓縮至約 100 KB。
- 不提供班級私人照片的存取。若未來納入，須增設私有群組、成員授權及私有 Storage bucket。

## 6. 核心 RPC

| RPC | 用途 |
|---|---|
| `p139_public_list_groups()` | 取得含有啟用人物的公開群組 |
| `p139_public_list_people(p_org_id)` | 取得該群組的公開人物、別名及優先級 |
| `p139_public_check_answer(p_person_id, p_answer)` | 回傳答題正誤與可能混淆人物，不寫入答題資料 |
| `p139_create_group(p_group_name)` | 系統管理者建立群組並取得該群組管理權 |
| `p139_list_my_organizations()` | 列出管理者可管理的群組 |
| `p139_list_people_for_admin(p_org_id)` | 取得管理群組人物清單 |
| `p139_save_person(...)` | 新增或更新人物資料及優先級 |
| `p139_set_person_active(...)` | 啟用或停用人物 |

## 7. 舊版照片升級

- V0.1 照片位於私有 `p139-private`；V0.2 以後新照片位於公開 `p139-public`。
- V0.4 僅讓已登入的群組管理者讀取 `p139-private`，供其使用介面將照片複製到 `p139-public`。原檔不刪除；群組管理者應先確認照片適合公開。
- V0.2/V0.3 上傳的照片已在 `p139-public`，不需遷移。

## 8. 版本限制

V0.4 使用公開練習資料，不含學生班級私密群組、伺服器端個人答題歷程、批次名單匯入或自助建立群組。個人紀錄綁定瀏覽器，無法跨裝置同步。
