# P139 新人的考驗 V0.1 系統規格

## 1. 定位

封閉式登入網頁，協助機構新人、學生與教職員透過照片練習記住彼此姓名。管理者維護團體人物資料；每位使用者自行決定練習優先級；錯誤紀錄只回饋給答題者本人。

## 2. 角色

| 角色 | 權限 |
|---|---|
| 團體管理者 | 管理人物照片、正式姓名、別名、啟用狀態與團體成員角色 |
| 一般成員 | 查看所屬團體人物、設定個人優先級、練習及查看自己的錯誤紀錄 |
| 未授權登入者 | 可登入，但沒有團體資料與照片存取權 |
| 未登入訪客 | 只能看到登入介面 |

註冊、驗證、密碼恢復與密碼變更由 P130 Account Center 處理。P139 不提供自助註冊或公開加入。

## 3. 主要資料物件

| 資料表 | 用途 |
|---|---|
| `TblP139Organization` | 機構或團體 |
| `TblP139Membership` | 使用者在團體中的角色與啟用狀態 |
| `TblP139Person` | 人物正式顯示姓名、照片路徑與啟用狀態 |
| `TblP139Alias` | 可接受的姓名別名 |
| `TblP139UserPriority` | 使用者對每個人物的個人熟悉優先級 |
| `TblP139AnswerEvent` | 個人答題內容、正誤、人物混淆對象與時間 |

## 4. 主要流程

1. 管理者登入並選擇其管理的團體。
2. 管理者逐筆輸入人物姓名與別名，選取照片；瀏覽器先縮小並壓縮照片，再上傳至 private bucket。
3. 管理者以已在 P130 註冊的 Email 將使用者加入團體。
4. 一般成員設定個人優先級：最想熟悉、正在熟悉、之後再熟悉。
5. 成員選擇其中一級，系統隨機排列該級人物；完成一輪後重新洗牌，避免連續輪次首尾重複同一人。
6. 成員輸入姓名。後端只接受該人物正式姓名或管理者設定的別名。
7. 錯誤時回傳正確姓名、該使用者自己先前最多三次錯誤答案，以及可辨識的人物混淆提示。

## 5. RPC

| RPC | 用途 |
|---|---|
| `p139_list_my_organizations` | 取得目前使用者已獲授權的團體 |
| `p139_list_people_for_priority` | 列出可設定個人優先級的人物 |
| `p139_set_my_priority` | 設定或清除本人對某人物的優先級 |
| `p139_get_quiz_cycle` | 取得隨機題目照片路徑，不回傳答案姓名 |
| `p139_submit_answer` | 後端比對姓名或別名，記錄結果與本人錯誤回饋 |
| `p139_list_people_for_admin` | 管理者檢視團體人物資料 |
| `p139_save_person` | 管理者新增或更新人物、別名與照片路徑 |
| `p139_set_person_active` | 管理者停用或重新啟用人物 |
| `p139_add_member` | 管理者將已註冊帳號加入團體 |
| `p139_bootstrap_organization` | 初次部署時由資料庫管理者建立團體與第一位管理者 |

## 6. 照片壓縮

- 僅接受瀏覽器可解碼的圖片格式，並輸出 JPEG。
- 先把最長邊縮至最多 1200 px，再依檔案大小調整 JPEG 品質與尺寸。
- 目標約 100 KB；照片內容不同，可能略高於目標。Storage bucket 限制單檔 1 MB。
- 私有路徑格式為 `{organization_uuid}/{person_uuid}.jpg`，並由 Storage RLS policy 限定團體成員讀取、管理者寫入。

## 7. 安全界線

- 所有 P139 資料表啟用 RLS；`anon` 與 `authenticated` 沒有直接資料表存取權。
- 前端不得直接查詢資料表或 View。讀寫皆由 P139 RPC 封裝並檢查 `auth.uid()`、團體成員狀態及管理者角色。
- RPC 使用固定 `search_path`。每個 `SECURITY DEFINER` 函式僅授予指定角色執行權。
- 答題 RPC 僅回傳當題判定及該使用者自己的歷史錯誤，不提供其他使用者答題資料。
- 私有照片使用授權後的限時簽名網址；不可使用公開 bucket 或公開 URL。
